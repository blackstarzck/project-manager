## 도구와 검수 loop

프로젝트 범위의 `frontend-design`, `web-design-guidelines`를 사용했고 출처 커밋을 DESIGN.md에 기록했다. React 변경은 Vercel React 검토 기준도 참고했다. REA는 기존 [원본 분석 기록](rea-analysis.md)과 [차이 점검표](fidelity-gaps.md)의 관찰 근거를 재사용했다. 원본 Manyfast 생성 요청은 **0회**다.

각 단계에서 기준 확인 → 작은 구현 → 자동 검사 → 브라우저 확인 → 독립 검토 → 수정 순서로 진행했다. Storybook에 기본·포커스·비활성·오류·로딩·긴 한글 상태와 탭/메뉴/모달 조작 예제를 추가했다. Playwright에 axe 및 고정 데이터 시각 비교를 추가했다. 일반 회귀는 테스트 공급자와 격리 DB를 사용한다.

주요 수정 사항:

- AI 요청 접수 응답이 늦게 도착하면 새로 입력한 요청문까지 지워지던 경로를 수정했다.
- 프로젝트 목록 요청 순서가 뒤바뀌었을 때 이전 검색/휴지통 응답이 현재 목록을 덮어쓰지 않게 했다.
- 프로젝트 생성 실패를 모달 내부에서 읽을 수 있게 했다.
- 캔버스 attribution과 일부 편집 도구의 낮은 대비를 수정했다.
- 와이어프레임 편집 선택 영역 안에 실제 버튼이 중첩되던 접근성 구조를 수정했다. 생성된 화면의 실제 버튼은 유지한다.
- 공통 모달의 포커스 복귀, 바쁜 상태 닫기 방지, 플로우 버전 메뉴의 Escape/대화상자 전환을 검증했다.
- axe가 자동 판정을 내리지 못한 `incomplete` 항목도 별도로 읽었다. 이 과정에서 플로우 SVG 연결선 글자의 낮은 대비와 도구 그룹의 역할 없는 `aria-label`을 발견해 수정 범위에 포함했다. 자동 위반 0건을 접근성 전체 보증으로 확대하지 않았다.

## 반영과 데이터 보존

운영 SQLite를 온라인 백업한 뒤 프로젝트 전체 행의 SHA-256, 프로젝트 수, schema version을 기록했다. 배포 전 자료는 `.qa-data/ux-refresh-20261016/production-backup.sqlite`, `production-before.json`, 이전 빌드는 `baseline-dist/`에 보존했다.

최종 candidate의 6개 파일을 `dist`에 반영하고, 3100이 실제 제공하는 HTML·JS·CSS·폰트·폰트 출처 파일의 SHA-256이 candidate와 같은 것을 확인했다. 새 번들은 `index-B-FY6_Nj.js`, 스타일은 `index-B5WFWiAP.css`다. 실행 중인 서버에서 새 정적 파일이 제공되어 서버 재시작 없이 반영했다. 인앱 브라우저를 직접 새로고침하여 새 번들, Pretendard 14px, 폰트 로드 완료와 콘솔 오류/경고 0을 확인했다. Groq 설정은 유지됐고 배포 검증에서 추가 생성 요청은 없다.

**초기 백업과 실제 반영 직전의 차이를 구분했다.** 최초 대조인 `production-after.json`은 `unchanged:false`다. 초기 백업(21:22 KST) 이후 **21:32:06 KST**에 기존 프로젝트의 보관 처리가 기록됐으며, 이는 첫 정적 빌드 반영(22:03 KST)보다 앞선 시점이다. 프로젝트 JSON의 변경 키는 `updatedAt`, `archivedAt`, `revision`뿐이고 문서 본문은 동일했다. 전체 DB에서는 해당 보관 이력에 따라 `audit`와 `revisions` 테이블도 각각 1행 증가했다. 현재 상태는 활성 프로젝트 0개·휴지통 1개다. 이 기록만으로 보관 동작의 주체를 단정하지 않는다.

## 사용자 관점 대행 UAT — 완료 / 직접 사용자 인수 — 미측정

사용자의 후속 요청에 따라 에이전트가 세 과제를 실제 브라우저로 직접 수행했다. PRD 작성·AI 일부 승인·버전 복원 **3/3 통과**, 에이전트 수행 시간은 각각 22초·30초·22초다. AI는 저장된 실제 Groq 결과를 로컬로 재생했으며 새 외부 호출은 없다. 사용성 개선 후보 4개와 상세 증거는 [대행 UAT 보고서](agent-uat-2026-10-16.md)에 기록했다. 이어서 4건을 수정하고 같은 세 과제와 실제 200% 확대를 재검수했다. 사용자가 승인한 읽기 전용 이력 조회 API 1개 추가를 포함한 최신 변경·검증·배포 상태는 [사용성 개선 재검수 보고서](uat-usability-fixes-2026-10-16.md)를 따른다. 아래 표는 사람의 직접 수행 기록을 위한 것으로, 대행 결과로 채우지 않는다.

에이전트 직접 검수와 자동 검사의 통과를 사용자 인수 승인으로 간주하지 않는다. 사용자가 별도 합성 프로젝트에서 아래 과제를 수행하고 시간을 기록해야 최종 UAT를 완료할 수 있다. AI 과제는 이미 생성된 검토 대기 제안이 있으면 그것을 사용하고, 새 실제 요청은 이번 검수 예산에 포함해 자동 실행하지 않는다.

| 과제 | 성공 조건 | 시작/종료·소요 시간 | 오조작·도움 요청 | 사용자 판정 |
|---|---|---|---|---|
| PRD 작성 | 항목/본문 작성 → 다른 문서 이동 → 돌아오기 → 새로고침 후 내용 유지 | 미기록 | 미기록 | 대기 |
| AI 일부 승인 | 변경 대상과 전후 내용 확인 → 일부만 선택 승인 → 나머지 검토 대기와 반영 내용 확인 | 미기록 | 미기록 | 대기 |

이번 범위의 한계: 휴대폰 전용 편집 UI와 독립 HTML 테마 재설계는 제외했다. Vite의 큰 번들 경고는 남으며 청크 분리는 후속 성능 개선 항목이다. 원본 서비스와 픽셀 단위 일치율을 주장하지 않는다.
