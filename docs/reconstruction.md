- **OBSERVED:** 원본 분리 창은 1440×1000에서 x86/y240, 약412×640. 상단 드래그 손잡이, 패널로 되돌리기, 닫기, 오른쪽 아래 크기 조절 손잡이가 있다. 관찰 후 도킹/접힘 상태를 복원했다.

## 3단계 차이 점검과 보완

2026-10-16 기존 공개 자산을 REA로 재분석하고 로그인된 원본의 플로우·빈 와이어프레임 탭을 읽기 전용으로 비교했다. 원본에서 새 생성 요청을 실행하지 않았고 이번 자동 검수에서는 합성 AI 응답을 사용했다. 실제 Groq 연동은 유지한다.

- **OBSERVED_STATIC / OBSERVED_RUNTIME:** 원본의 새 플로우 생성과 수정본 생성을 구분했다. 로컬은 현재 버전 편집·같은 그룹의 AI 수정본·새 그룹 생성을 제공하고, 승인 시점에 새 버전을 확정한다. 이전 버전과 화면은 보존하며 결과 버전으로 바로 이동할 수 있다. 수동 사본은 `현재 버전 복제`로 구분한다.
- **IMPLEMENTED:** 와이어프레임에서 플로우 그룹/버전을 직접 선택하고 저장 후 전환한다. 미생성 페이지 추가와 기존 화면 개선을 나누고, 체크한 대상 ID만 AI에 요청한다. 원본의 독립 와이어프레임 버전 이력 전체를 재현한 것은 아니다.
- **IMPLEMENTED:** 분리 AI 창의 원본 최대 비율(너비 55%, 높이 85%)과 최소 크기 우선순위를 반영했다. 작은 화면에서의 경계 보호와 요청 작성 상태를 유지한다.
- **FIXED:** 표 제목을 순차 입력할 때 뒤쪽 셀이 사라지는 문제, 비활성 버전에서 참조하는 기능을 삭제해 저장 불가 상태가 되는 문제, 자동 정리의 늦은 결과가 다른 버전 또는 최신 수동 편집을 덮는 문제를 수정했다. 실패 재현과 동일 시나리오 재검수는 [검수 기록](qa-loop.md)에 보존한다.

공개 자산의 정적 분기와 실제 서버 정책은 구분한다. 남은 차이와 우선순위는 [차이 점검표](fidelity-gaps.md)를 기준으로 추적한다.

## 4단계 독립 화면 버전과 보관·복구

2026-10-16 기존 공개 자산 두 개를 REA로 재분석했다. 원본 사이트의 생성·수정·삭제·내보내기 호출과 실제 Groq 호출은 이번 단계에서 하지 않았다. 근거와 분석 상한은 [REA 기록](rea-analysis.md)의 4차 감사에 남긴다.

- **OBSERVED_STATIC → IMPLEMENTED:** 플로우 버전과 화면 버전 식별자가 분리되고 generate/append/regenerate의 기준·선택 페이지가 다르다는 공개 클라이언트 구조를 반영했다. 플로우마다 독립 화면 버전의 복제·이름 변경·전환을 제공한다. 추가·재생성의 승인 시 새 화면 버전을 만들고 원본 및 선택하지 않은 화면을 보존하는 정책은 독립 설계다.
- **IMPLEMENTED / independent design:** 그룹·플로우 버전·화면 버전의 휴지통·복원, 마지막 활성 항목 보호, 선택 버전의 대체와 부모부터 복원하는 규칙을 추가했다. 원본 휴지통·복구·영구 삭제 정책은 확인하지 않았다.
- **OBSERVED_STATIC → IMPLEMENTED:** Tablet 768×1024를 편집·미리보기·HTML/PNG에 적용했다. 헤더·사이드바·푸터는 대상 화면을 골라 복사하고 본문은 보존한다. 원본 공유 DSL의 자동 추론·동기화 전체를 재현한 것은 아니다.
- **IMPLEMENTED:** 스트리밍 중 완전한 화면 객체가 도착한 개수와 이름을 표시한다. 이 수치는 전체 응답의 검증·제안 승인·부분 성공을 뜻하지 않는다. 페이지별 부분 성공 승인과 실패 페이지 재시도는 남아 있다.
- **FIXED:** 편집 중 다른 탭에서 버전이 바뀌면 초안의 원래 플로우/화면 버전과 수정 번호를 유지한다. 명시적 복귀 또는 보관된 원본의 복원 후 저장을 제공하고, 원본 자체가 외부 수정된 경우에는 덮어쓰지 않는다. 공통 영역 적용도 컨테이너별 100개·전체 500개·깊이 8단계 제한을 편집 전에 검사한다.

기존 데이터와 미승인 AI 제안의 원본 버전 연결은 DB 마이그레이션에 포함했다. 백업·가져오기·프로젝트 복제에는 보관된 이력도 포함한다. 검수 결과는 [검수 기록](qa-loop.md)을 따른다.

## 5단계 페이지별 재시도와 자동 동기화

2026-10-16. REA의 기존 retained Evidence와 같은 공개 자산을 재사용하여 페이지 완료·성공/실패/취소 집계, 공유 DSL이 본문을 유지하면서 내비게이션 영역에 우선 적용되는 구조를 확인했다. partial graph의 두 문자열 trace는 no-match였으며 기능 부재로 해석하지 않았다. 원본이나 Groq에 실제 생성 요청은 추가하지 않았다.

- **IMPLEMENTED / independent design:** 추가·재생성을 페이지별 순차 호출로 나누고 성공 결과와 실패 사유를 보관한다. 최초 호출 포함 페이지당 최대 3회, 실패·취소한 페이지만 사용자가 재요청하며 자동 재시도는 없다. 취소/재시작 후 성공 결과를 명시적으로 검토할 수 있다.
- **IMPLEMENTED:** 일부 성공 결과의 승인은 하나의 새 화면 버전을 만든다. 실패한 기존 화면은 보존하고 실패한 새 페이지는 추가하지 않는다. 원본 버전·수정 번호·모델 및 중복 명령 검사로 잘못된 재시도와 중복 결과를 막는다. 승인 이후 같은 실행의 재시도 대신 결과 버전에서 새 요청을 시작한다.
- **IMPLEMENTED / independent design:** 공통 영역의 기준과 대상을 명시적으로 연결하고, 기준 변경을 자동 반영한다. 대상은 연결 해제 후 개별 편집하며 본문은 독립이다. 기준 삭제나 기기 변경 시 내용은 유지하고 연결만 해제한다. 연결 정보와 요소 ID는 저장·백업·복제·내보내기에서 일관되게 처리한다.
- **FIXED:** 같은 연결을 다시 적용할 때 본문 모달 링크가 끊기는 문제, 기준 영역 삭제 후 실행 취소 조합으로 해제된 연결이 살아나는 문제를 수정했다. 화면 수 제한도 로컬 변경 전에 검사한다. 재시도 이력이 많아져도 표시 중인 실행의 현재 제안과 승인 결과를 함께 조회하여 검토·결과 이동 버튼을 유지한다. 실패 재현과 회귀 증거는 검수 기록에 남긴다.

원본 서버의 재시도/과금/취소/공유 영역 소유권 정책은 확인하지 않았다. 로컬 정책과 원본 관찰의 경계는 [REA 기록](rea-analysis.md), 동작 계약은 [데이터·API 계약](contract.md)에 명시한다.

## 6단계 공통 영역 자동 추론과 입력 보존

2026-10-16. 기존 공개 자산을 REA로 추적했으며 원본 사이트나 Groq 생성 요청은 추가하지 않았다. 공유 DSL의 렌더링과 `nav=none` 분기를 확인했지만 비공개 추론 알고리즘은 미확인으로 유지했다.

- **IMPLEMENTED / independent design:** 동일한 기기의 헤더·사이드바·푸터에서 구조·문구·스타일·동작이 일치하는 영역을 자동으로 찾는다. 기준 소유권과 제외 사유를 표시하고 검토한 대상에만 연결을 추가한다. 기존 요소를 다시 만들지 않아 요소 ID·본문·모달 참조를 유지한다.
- **IMPLEMENTED:** 기존 연결, 모호한 기준, 중복 영역, 빈 틀, 영역 밖 모달 참조를 보수적으로 처리한다. 분석 이후 내용·버전이 바뀌면 적용을 막고 다시 분석하도록 한다. 화면별 자동 찾기 제외 설정은 저장·복제·백업·AI 재생성에서 유지한다.
- **FIXED:** 4,001자 이상 붙여넣기로 서버 저장 한도를 넘는 초안이 만들어지는 문제를 브라우저에서 재현했다. 입력 한도와 변경 전 검사를 추가하고 글자 수를 표시한다. 기존 내용과 실행 취소 기록은 유효한 변경에만 갱신한다.

로컬 자동 추론은 AI를 호출하지 않는다. 의미가 비슷하지만 서로 다른 메뉴를 합치거나 빈 화면에 공통 영역을 작성하는 기능과 구분한다. 최종 검수 결과와 실제 공급자 검증의 한계는 [검수 기록](qa-loop.md)에 남긴다.

## 화면·행동 기준

- 프로젝트: 생성·이름/설명 수정·복제·휴지통·복원·검색.
- PRD: 개요, 문제 및 해결 방안, 타겟 및 시나리오, 성공·위험 요소, 속성 설정. 항목 추가/삭제, 리치 텍스트 편집, 저장 상태.
- 기능명세: 요구사항→기능→하위 기능. 그래프·디렉토리·도큐먼트 뷰가 동일 엔터티 사용. 우선순위·진행 상태·역할·인수 조건·PRD 참조.
- 플로우: 시작·페이지·데이터·분기·액션, 노드/연결선/섹션, 이동/편집/저장/복원.
- 와이어프레임: 페이지 목록·Desktop/Tablet/Mobile·중첩 요소 편집·공통 내비게이션 복사와 선택적 자동 동기화·탐색 모드·선택 범위 생성. 플로우별 독립 화면 버전과 갱신 필요 표시.
- AI: 실제 Groq 생성·작업 상태·취소·재시도·변경 전후 검토·전체 또는 개별 승인/거절. 최종 데이터에는 승인만 반영.
- 내보내기: PRD/기능 Markdown, 기능 XLSX, 플로우 Mermaid, 화면 HTML, 화면 캡처 PNG. 시작 시점 문서 버전 고정.
- 기록: 저장 버전·복원, 프로젝트 JSON 백업/새 프로젝트로 복원.

## 독립적인 두 판정

근거: OBSERVED / DOCUMENTED / INFERRED / UNKNOWN.

구현: TESTED / PARTIAL / BLOCKED / NOT_IMPLEMENTED.

자동 테스트 통과가 원본 동작 일치를 증명하지는 않는다. 직접 관찰되지 않은 항목은 기능 검사에 통과해도 원본 일치 미검증 상태로 유지한다. 기능별 기준 및 결함은 qa-loop.md에서 관리한다.
## 7단계 확장 추론과 실제 AI 검수

2026-10-16. 기본 공통 영역 찾기는 정확 일치를 유지한다. `유사 메뉴와 없는 영역도 찾기`를 켜면 같은 이동 대상과 구조를 가진 메뉴의 표현 통합, 없는 공통 영역의 추가, 공통 영역이 전혀 없는 화면들에 기존 페이지 목록을 이용한 헤더 생성을 검토할 수 있다. 비정확 제안은 기본 미선택이며, 변경 내역과 신규 메뉴 미리보기를 확인하고 적용한다. 본문·기존 ID·모달 참조·버전과 기존 소유권을 보존한다.

실제 Groq 검수는 별도의 합성 프로젝트와 임시 DB에서 완료했다. 실제 요청 5회 중 4회 성공, 1회 사용량 제한 응답이 있었으며 자동 재시도하지 않았다. 대기 시간 이후 명시적인 한 번의 재개로 성공 결과를 재사용하여 실패 페이지 재시도, 부분 승인, 취소 후 재시작을 확인했다. 사용자 프로젝트와 원본 Manyfast 생성 요청은 사용하지 않았다. [검수 범위와 결과](live-integration.md).

원본의 공개 문서·스크린샷과 보관 자산의 추가 REA 분석으로 미리보기의 오른쪽 페이지 목록, 하단 탐색·배율 도구, 프레임 내부 스크롤, 상호작용 힌트를 보완했다. 생성 대상과 화면 목록에는 검색·섹션 구분을 추가했다. 파란 상호작용 힌트는 PNG에 포함되지 않도록 처리한다. 시각 기준과 원본에서 확인하지 못한 정책은 [REA 기록](rea-analysis.md), 최신 반복 검수는 [QA 기록](qa-loop.md)에 분리해 남긴다.
