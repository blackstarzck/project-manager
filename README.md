# Planit — 로컬 AI 기획 워크스페이스

PRD → 기능명세 → 유저플로우 → 클릭 가능한 와이어프레임을 작성하는 한국어 로컬 웹앱입니다. Manyfast의 공식 가이드, 로그인된 기존 프로젝트 화면, REA의 공개 JavaScript 분석을 참고하여 별도로 구현했습니다. 원본에서 생성·수정 요청 없이 관찰했으며, 원본과의 일치 검증은 기능 검증과 구분합니다.

## 실행

Node.js 24 이상과 pnpm을 사용합니다.

```powershell
pnpm install
pnpm dev
```

개발 화면: http://127.0.0.1:5173 (서버 3100). 프런트엔드 변경은 즉시 반영됩니다. 서버 코드를 수정하면 `Ctrl+C` 후 다시 실행하세요.

```powershell
pnpm build
pnpm start
```

빌드한 앱: http://127.0.0.1:3100

## Groq 설정

프로젝트 루트의 `.env` 또는 `.env.txt`를 서버에서 읽습니다. 사용자가 제공한 `.env.txt`는 그대로 사용할 수 있습니다. 키는 브라우저로 전달하지 않으며 Git에서 제외됩니다.

```dotenv
GROQ_API_KEY=여기에_본인의_키
GROQ_MODEL=openai/gpt-oss-120b
```

연결 상태는 앱에서 확인할 수 있습니다. 인증 실패·사용량 제한·네트워크 오류는 화면에 표시되며 다른 서비스로 자동 전환하지 않습니다. AI 요청 시 현재 프로젝트의 기획 내용과 요청문이 Groq로 전송됩니다. API 사용량은 해당 Groq 계정에 반영됩니다. 수동 편집은 API 연결 없이도 가능합니다.

AI 출력은 변경 제안으로 저장됩니다. 승인 전에 문서를 바꾸지 않습니다. 변경 대상을 사용자가 먼저 수정한 경우 충돌을 표시합니다. 취소·거절·실패 시 기존 문서를 유지합니다.

## 데이터와 복원

Windows 기본 데이터 위치는 `%LOCALAPPDATA%\ProjectManager\data\workspace.sqlite`입니다. `PM_DATA_DIR` 환경변수로 위치를 변경할 수 있습니다. 빌드 폴더와 데이터 위치는 분리됩니다.

앱의 프로젝트 백업은 검증 가능한 JSON 파일입니다. 복원은 기존 프로젝트를 덮어쓰지 않고 새 프로젝트를 만듭니다. 프로젝트 삭제는 휴지통으로 이동하며 다시 복원할 수 있습니다. 문서 버전 복원은 새 버전을 생성하고 기존 기록을 보존합니다.

## 검수 loop

```powershell
pnpm typecheck
pnpm test
pnpm test:e2e
pnpm build:storybook
```

자동 검수는 별도 임시 DB와 주입한 테스트 AI를 사용합니다. 실제 Groq 호출 검수와 구분합니다. E2E는 설치된 Google Chrome을 사용하며 다른 경로는 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`로 지정할 수 있습니다.

공통 UI의 기본·포커스·비활성·오류·로딩·긴 한글 상태와 키보드 조작은 `pnpm storybook`으로 확인할 수 있습니다. 접근성·시각 회귀만 실행하려면 `pnpm exec playwright test -c tests/playwright.config.ts ux-accessibility`를 사용합니다. 시각 기준은 Windows·Chrome·로컬 Pretendard·고정 합성 데이터로 생성하며, 변경 이미지를 직접 검토한 뒤에만 갱신합니다. 자동 검사는 axe의 critical/serious 위반을 검사 제외 없이 확인합니다.

문서 중심 UI 기준은 [DESIGN.md](DESIGN.md), 이번 개선과 실제 200% 확대·빌드 앱·Groq 검수 및 사용자 최종 UAT 상태는 [UX/UI 구현 보고서](docs/ux-ui-implementation-2026-10-16.md)에 기록했습니다.

후속 UAT에서 발견한 사용성 4건의 수정과 재검수는 [사용성 개선 보고서](docs/uat-usability-fixes-2026-10-16.md)를 참고하세요. 보고서에 연결된 `.qa-data/` 원시 증거, 운영 DB와 환경 파일은 로컬에만 보관하며 저장소에 포함하지 않습니다. 재현에 필요한 테스트 코드와 시각 비교 기준 이미지는 포함합니다.

검수는 독립 담당자가 재현 → 수정 → 같은 시나리오 재검사 → 전체 회귀 → 실제 산출물 확인 순서로 수행합니다. 중첩 화면, 플로우·화면 버전의 독립성, AI 패널 상태, 늦은 응답과 다른 탭의 편집 경합, 보관·복원, 기존 DB 이전 및 내보내기를 검사합니다. 최종 실행 결과와 발견된 결함은 [검수 기록](docs/qa-loop.md)에 보관합니다.

초기 단계에서는 모의 AI 자동 검사와 별도로 실제 Groq의 네 단계 생성·승인, 중첩 화면 생성, 복사 버전의 독립성 및 서버 재시작 후 저장 유지를 확인했습니다. 7단계에서는 별도 합성 예제로 페이지별 실패 재시도·부분 승인·취소 후 재시작도 실제 생성 결과와 연결해 검수했습니다. 총 실제 요청 5회(성공 4회·사용량 제한 1회)의 범위와 명시적 재개 기록은 [실제 연동 결과](docs/live-integration.md)를 참고하세요.

실제 API를 다시 검사하려면 `pnpm exec tsx scripts/live-smoke.ts`를 명시적으로 실행합니다. 합성 예제로 실제 Groq 사용량을 소모하며 일반 테스트에는 포함되지 않습니다. 결과는 `.qa-data/live-*/report.json`에 저장됩니다. 실패한 실행은 `--resume .qa-data/live-해당번호`로 성공한 단계를 건너뛰고 재개할 수 있습니다.

중첩 화면만 실제 API로 확인하려면 `pnpm exec tsx scripts/live-nested-smoke.ts`를 실행합니다. 별도 임시 DB와 합성 도서관 예제를 사용하고 실제 생성 1회를 요청합니다. 결과는 `.qa-data/live-nested-*/report.json`에 저장합니다. 일반 회귀 검수에 이 명령을 포함하지 않습니다.

검수 기준·결함·실행 결과는 [검수 기록](docs/qa-loop.md), 설계는 [데이터·API 계약](docs/contract.md), 원본 근거와 범위는 [재현 명세](docs/reconstruction.md), 정적 분석은 [REA 기록](docs/rea-analysis.md)을 참고하세요.

원본과 남은 차이, 근거의 확인 수준, 보완 순서는 [차이 점검표](docs/fidelity-gaps.md)에 정리합니다. 원본 생성 크레딧을 사용하는 자동 비교는 수행하지 않습니다.

## 중첩 화면·플로우 버전·AI 패널 사용

문서가 기본 작업 공간이며 AI는 왼쪽 레일에서 필요할 때 엽니다. 창이 좁아지면 AI를 오버레이로 표시하고 문서 구조·목록·속성을 접어 작업 공간을 확보합니다. AI 초안과 사용자가 선택한 패널 배치는 유지합니다. PRD·기능명세·유저플로우·와이어프레임 탭은 현재 편집 저장에 성공한 뒤 이동하며, 저장 실패 시 초안과 주소를 유지합니다. 문서 주소는 `#project/{id}/{prd|features|flow|wireframes}` 형식입니다.

- **와이어프레임:** row/column/grid, header/sidebar/body/footer, 카드·박스·표·모달을 중첩합니다. 왼쪽 레이어에서 깊은 요소를 선택하고 오른쪽 속성에서 상위 컨테이너·정렬·간격·크기·색상과 클릭 동작을 편집합니다. 표 제목을 바꿔도 기존 셀은 보존하며, 열 삭제는 별도 버튼으로 실행하고 되돌릴 수 있습니다. 미리보기에서 화면 이동·뒤로가기·모달을 실행하고 HTML 또는 PNG로 내보낼 수 있습니다. 화면당 500개 요소, 중첩 8단계까지 지원합니다.
- **독립 플로우 버전:** 유저플로우 왼쪽에서 새 그룹을 만들거나 ‘현재 버전 복제’로 플로우와 화면을 함께 복사합니다. AI 생성에서는 ‘새 플로우 만들기’ 또는 ‘현재 플로우의 AI 수정본’을 선택합니다. 승인 시 새 결과를 추가하며 원래 버전은 보존됩니다. 새 AI 버전의 와이어프레임은 그 버전에서 따로 생성합니다. 대화창의 ‘현재 플로우 편집’은 선택 버전을 직접 수정하는 제안입니다. 실패·취소·거절로 빈 버전이 생기지 않습니다.
- **버전 전환:** 와이어프레임 위의 플로우 버전 선택기로 바로 전환할 수 있습니다. 전환 전에 현재 편집을 저장하며 저장 실패 시 초안을 유지합니다. AI 제안도 요청을 시작한 버전에 연결됩니다. 이전 데이터는 첫 실행에서 기본 그룹·버전으로 이동하고 백업에는 전체 버전이 포함됩니다. 기능 삭제 전에는 비선택 버전의 참조까지 검사합니다.
- **화면 생성 범위:** 여러 화면을 생성하거나 개선할 때 ‘미생성 페이지 추가’와 ‘기존 화면 개선’을 구분하고 대상 페이지를 선택합니다. 요청 전 선택 개수와 기준 버전을 확인할 수 있습니다. 취소하면 AI 요청을 보내지 않습니다. 한 화면의 ‘이 화면 AI 개선’도 계속 사용할 수 있습니다.
- **분리형 AI 패널:** ‘창으로 띄우기’로 분리하고 상단을 끌어 이동하거나 오른쪽 아래를 끌어 크기를 조절합니다. ‘패널로 되돌리기’로 도킹합니다. 위치·크기·열림 상태는 다시 열어도 유지되고, 전환 중 작성한 요청문과 실행 상태도 유지됩니다.

## 독립 화면 버전과 공통 영역

와이어프레임의 **화면 버전** 선택기에서 같은 플로우의 여러 화면 구성을 관리합니다. `화면 버전 복제`는 현재 화면들을 독립된 사본으로 만들고, 이름을 바꾸거나 이전 버전으로 전환할 수 있습니다. 전환 전에 편집을 저장하며 각 버전의 편집 기록과 화면 연결을 구분합니다. 기존 저장 데이터는 첫 화면 버전으로 이전됩니다.

그룹·플로우 버전·화면 버전은 메뉴에서 휴지통으로 옮기고 `버전 휴지통`에서 복원합니다. 마지막 활성 항목은 보호하며, 현재 항목을 옮기면 남아 있는 버전을 선택합니다. 상위 그룹이나 플로우도 휴지통에 있다면 상위 항목부터 복원합니다. 복원해도 현재 선택은 자동으로 바뀌지 않습니다.

다른 탭에서 버전을 바꾸거나 보관하여 저장에 실패하면 편집 중인 초안을 유지합니다. 안내 버튼으로 원래 버전에 돌아가 저장할 수 있으며, 원래 버전이 보관된 경우에는 명시적인 `원래 버전 복원 후 돌아가 저장` 동작을 제공합니다. 원래 버전 자체가 외부에서 수정됐다면 충돌로 처리하여 덮어쓰지 않습니다.

AI의 `미생성 페이지 추가`와 `기존 화면 개선`은 페이지마다 순차적으로 Groq를 호출하고, 승인하면 **새 화면 버전**을 만듭니다. 기존 버전과 선택하지 않은 본문을 보존하며, 연결된 공통 영역은 기준 화면의 변경을 따릅니다. 대화창에서 현재 버전을 직접 편집하는 모드도 선택할 수 있습니다. 기존 직접 편집 모드의 `화면 데이터 수신`은 응답에 도착한 화면 객체 수이며, 전체 응답 검증과 사용자 승인은 별도입니다.

화면 기기는 Desktop·Tablet·Mobile을 지원합니다. Tablet은 768×1024 기준으로 미리보기와 HTML/PNG에 반영됩니다. 프로젝트 설정에서 AI에 전달할 이용 기기도 지정할 수 있습니다.

화면 속성의 `공통 내비게이션 적용`으로 헤더·사이드바·푸터 중 필요한 영역과 대상 화면을 선택합니다. 기본 동작은 복사이며, **이후 변경도 자동 동기화**를 선택하면 같은 기기의 화면들이 기준 화면에 연결됩니다. 기준 영역을 수정하면 현재 화면 버전의 연결된 영역에 즉시 반영되고 본문은 유지됩니다. 연결된 영역은 기준 화면에서 편집하거나 `연결 해제` 후 개별 편집합니다.

기준 화면·영역을 삭제하거나 연결된 화면의 기기를 바꾸면 마지막 내용을 보존하고 연결을 해제합니다. 이 해제는 기준 화면의 실행 취소만으로 되돌아오지 않습니다. 다른 화면 버전의 사본에는 전파되지 않으며, HTML/PNG·백업에도 반영된 내용을 저장합니다.

**공통 내비게이션 찾기**는 같은 기기의 화면에서 구조·문구·스타일·이동 동작이 일치하는 영역을 자동으로 찾습니다. 제안된 기준과 대상을 확인하고 `선택한 공통 영역 연결`을 누르면 기존 요소 ID·본문·모달 연결을 보존한 채 동기화를 시작합니다. 분석 후 화면이 바뀌면 `다시 분석`해야 합니다. 화면 속성의 `공통 영역 자동 찾기에서 제외`로 개별 화면을 후보에서 뺄 수 있습니다. 기존 연결은 유지되므로 필요하면 별도로 연결을 해제합니다.

자동 찾기는 로컬에서 처리하며 Groq를 호출하지 않습니다. 기본값은 정확히 같은 영역만 제안합니다. `유사 메뉴와 없는 영역도 찾기`를 켜면 이동 대상과 구조가 같은 메뉴의 문구·스타일 통합, 없는 공통 영역 추가를 함께 제안합니다. 공통 영역이 전혀 없는 화면들에는 현재 화면 이름과 실제 이동 대상을 사용한 헤더 초안을 제안합니다. 변경 제안은 기본 미선택이며 변경 내역·미리보기를 확인한 뒤 적용합니다. 여러 기준이 충돌하는 영역, 빈 틀과 다른 영역의 모달을 참조하는 경우에는 제외 이유를 보여 줍니다. 와이어프레임 요소 내용은 4,000자까지 입력하며 입력란에 글자 수를 표시합니다.

실제 페이지 작업 검수 스크립트는 `pnpm exec tsx scripts/live-page-jobs-smoke.ts --allow-live`입니다. 합성 예제와 임시 DB만 사용하고 실제 요청은 최대 6회로 제한합니다. 일반 자동 테스트에는 포함되지 않으며, 다시 실행하면 Groq 사용량이 발생합니다.

## 페이지별 실패 재시도와 부분 결과

미리보기에서는 오른쪽의 섹션별 페이지 목록을 검색할 수 있습니다. 아래 도구로 이전·다음 페이지, 배율·맞춤, 직접 편집을 사용할 수 있으며 긴 내용은 화면 안에서 스크롤합니다. 빈 공간을 누르면 작동하는 연결과 입력란에 파란 힌트가 잠시 나타납니다. 힌트는 PNG로 내보낼 때 포함되지 않습니다. `페이지 다시 생성`은 현재 화면만 변경 제안으로 요청하며, 승인 전까지 저장된 문서는 유지됩니다.

새 버전 생성에서는 페이지별 대기·생성 중·검증 완료·실패·취소 상태와 시도 횟수를 표시합니다. 성공한 페이지의 검증 결과는 보관하며, **실패한 화면만 다시 시도**에서 재시도할 페이지를 선택합니다. 성공한 페이지는 다시 호출하지 않습니다. 자동 재시도는 없고, 최초 호출을 포함하여 페이지당 최대 3회입니다. 각 호출은 Groq 계정의 사용량에 반영됩니다.

일부 페이지만 성공해도 `성공한 화면만 승인`으로 새 결과 버전을 만들 수 있습니다. 실패·취소한 기존 화면은 그대로 보존하고 실패한 새 페이지는 추가하지 않습니다. 공통 영역 동기화가 실패 화면의 내용을 바꾸게 되는 경우 새 결과에서만 해당 연결을 해제하며, 승인 화면에 이를 표시합니다. 원본 버전은 유지됩니다.

취소나 재시작 후에도 완료한 결과는 남습니다. `보관된 성공 화면 검토`로 명시적으로 제안을 준비하거나 미완료 페이지만 재시도합니다. 결과를 승인한 뒤에는 그 실행을 다시 재시도하지 않으며, 결과 버전에서 새 요청을 시작합니다. 원본이 수정되거나 다른 버전이 선택된 경우에는 충돌을 안내하고 보관된 성공 결과를 유지합니다.

## 남은 범위

원본의 채워진 와이어프레임은 무료 크레딧을 사용하지 않기 위해 직접 생성하지 않았습니다. 공개 JavaScript의 REA 분석, 로그인 화면의 비소모 조작, 공식 문서의 완성 화면을 근거로 재현했습니다. 전체 픽셀 일치나 원본 서버 동작과의 동일성을 검증한 것은 아닙니다. 팀 계정·실시간 협업·외부 공개 링크·Claude Code·MCP는 별도 서비스 운영 범위입니다. 페이지별 재시도·부분 승인·공통 영역 자동 추론과 소유권·보관·복구 규칙은 데이터 보존을 위한 독립 설계입니다.
